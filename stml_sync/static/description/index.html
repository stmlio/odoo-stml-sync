STML Sync

Transactional batch upserts for integrations that write a lot of records

One round-trip per batch, one savepoint per record

Integration tools that push data into Odoo over RPC usually pay one HTTP round-trip per record. STML Sync adds a single server-side method that creates or updates up to 1,000 records of one model in one call. Every record runs in its own database savepoint: a row that fails validation or access control is rolled back and reported by position, while the other rows of the same batch are committed together.

Measured on Odoo 19 with 2,000 products: re-running a sync where half the prices changed took 4 seconds through the module against 30 seconds record by record.

What the module exposes

ping()

Returns the module version, the Odoo version and the list of supported capabilities, so a client can detect the module and fall back to stock RPC when it is absent.

batch_upsert(model, records, options)

Takes a list of records, each with an optional id (update) or none (create), ORM-ready values, and an optional xml_id that is created or repaired for the record. Returns one result per record with the record id and the action taken: created, updated, skipped or error.

Skip unchanged rows

With skip_unchanged the server compares the submitted values with the stored ones and leaves records that would not change untouched, so write dates and chatter stay clean.

Safe retries

Each call carries a client-minted operation_id. A retry after a timeout returns the stored result of the first attempt instead of creating duplicates.

Clear errors

Failures are classified as ValidationError, AccessError, MissingError, UserError, IntegrityError or Other, with Odoo's own message, so the caller can decide what to retry and what to report.

Security and data

  • Every call runs as the authenticated user. Access rights and record rules apply unchanged; the module never uses sudo.
  • No data leaves your Odoo server. The module makes no outbound requests and needs no account or key.
  • The idempotency ledger stores result summaries only (record ids, actions, error text), never the submitted values. Users only see their own entries, and a daily job removes entries older than seven days.
  • No UI, no menus, no settings. Install it and it is ready.

Compatibility

Odoo 16, 18 and 19, Community and Enterprise, on-premise or on Odoo.sh. Depends on base only. Built for the STML sync engine, but any RPC client can call it.
